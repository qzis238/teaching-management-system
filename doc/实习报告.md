# 专业综合实训报告

## 一、系统概述

### 1.1 研究背景

随着信息技术的飞速发展，教育行业正经历着深刻的数字化转型。传统的教学管理方式依赖纸质记录和人工操作，存在效率低下、数据易丢失、信息共享困难等问题。各类学校和培训机构在日常运营中需要管理大量的学生信息、班级信息、课程安排、考勤记录、成绩数据和作业批改等事务，这些工作的繁琐性和重复性对管理人员和教师构成了较大负担。

在此背景下，开发一套功能完善、操作便捷的教学数字平台管理系统具有重要的现实意义。该系统能够将教学管理的各个环节数字化、自动化，实现学生信息管理、班级管理、课程排课、考勤打卡、成绩管理、作业发布与批改等核心业务的信息化处理，有效提升教学管理的效率和质量，降低人工操作的出错率，为教学决策提供数据支持。

### 1.2 国内研究现状

近年来，国内教育信息化建设取得了长足进步。从早期的单机版教务管理软件，到如今基于云计算和大数据的智慧校园平台，教学管理系统经历了从简单到复杂、从孤立到集成的演进过程。

目前，国内主流的教学管理系统主要分为两类：一类是面向高等院校的综合教务管理系统，如正方教务系统、青果教务系统等，功能涵盖教务、学籍、选课、成绩等多个方面，但系统庞大且定制化程度高，不适合中小规模教学机构使用；另一类是面向K12教育和培训机构的轻量级管理平台，如校管家、校宝在线等，侧重于家校沟通和简单的学生管理，在课程排课、考勤分析、作业管理等深度功能上支持不足。

因此，针对中小规模教学场景，开发一套功能聚焦、界面友好、部署便捷的教学数字平台管理系统，具有较好的应用价值和市场前景。

## 二、技术介绍

### 2.1 前端技术

系统前端采用 HTML + CSS + JavaScript 原生技术，结合 Vue 3 框架、Element Plus 组件库和 ECharts 图表库进行开发，所有依赖通过 CDN 引入，无需构建工具。

**Vue 3** 是一款渐进式 JavaScript 框架，采用 Composition API 设计模式，提供了响应式数据绑定、组件化开发和虚拟 DOM 等核心能力。Vue 3 的 Proxy 响应式系统相比 Vue 2 的 Object.defineProperty 方案，支持更深层次的动态响应，且性能更优。

**Element Plus** 是专为 Vue 3 设计的桌面端 UI 组件库，提供了表单、表格、弹窗、分页、导航菜单等丰富的企业级组件，能够快速搭建美观、统一的管理后台界面。其表单校验功能可以方便地实现前端输入验证，配合后端校验形成双重保障。

**ECharts** 是百度开源的数据可视化图表库，支持柱状图、折线图、饼图等多种图表类型，能够将统计数据以直观的图形方式展示。在仪表盘页面中，使用 ECharts 绘制班级学生人数分布柱状图和近 7 天出勤趋势折线图。

系统通过 Vue Router 实现前端路由，所有页面组件集成在单一 HTML 文件中，以 SPA（单页应用）模式运行，用户在不同功能模块间切换时无需刷新页面，体验流畅。

### 2.2 后端技术

系统后端采用 Java 语言开发，基于 Spring Boot + MyBatis 技术栈构建。

**Spring Boot** 是当前 Java 生态中最流行的微服务开发框架。它基于"约定优于配置"的理念，通过自动配置大幅简化了 Spring 应用的搭建和开发过程。内嵌的 Tomcat 容器使应用无需单独部署 Web 服务器，直接以 Jar 包形式运行。Spring Boot 的 starter 启动器机制可以一键引入 web、数据库、缓存等各类依赖。

**MyBatis** 是一款优秀的持久层框架，它通过 XML 或注解的方式将 SQL 语句与 Java 方法映射，消除了 JDBC 代码的手动编写和参数设置。MyBatis 支持动态 SQL 构建，能够灵活应对复杂的查询场景。在本系统中，所有 SQL 参数均使用 `#{}` 占位符进行参数化传递，从根本上杜绝了 SQL 注入风险。

**Maven** 作为项目构建和依赖管理工具，统一管理了 Spring Boot Starter、MyBatis Starter、MySQL Connector、JWT 库等依赖，保证了项目的可移植性和版本一致性。

### 2.3 数据库

系统数据库选用 **MySQL 8.0**。MySQL 是开源的关系型数据库管理系统，具有体积小、速度快、成本低等优点，广泛应用于中小型Web应用。系统使用 InnoDB 存储引擎，该引擎支持事务（ACID）、行级锁和外键约束，能够保证数据的一致性和并发操作的安全性。

数据库字符集采用 utf8mb4，支持完整的 Unicode 字符（包括 emoji 等四字节字符）。所有数据表统一采用逻辑删除策略（is_deleted 字段），删除操作仅标记记录状态而非物理删除，确保数据可追溯、可恢复。

## 三、需求分析

### 3.1 可行性分析

**技术可行性**：系统采用成熟的技术栈。前端 Vue 3 + Element Plus 拥有完善的文档和活跃的社区，能够满足管理系统的界面和交互需求。后端 Spring Boot + MyBatis 是业界广泛使用且经过大量项目验证的框架组合。MySQL 数据库能够稳定存储和处理教学管理的数据量。开发所需工具均为免费开源软件，无许可证成本。从技术角度看，系统开发完全可行。

**经济可行性**：系统开发和运行成本低。开发工具（IntelliJ IDEA Community Edition、VS Code）免费使用，所有技术框架开源，运行环境仅需一台普通配置的服务器或PC。相比商业教学管理系统动辄数万元的授权费用，本系统具有显著的成本优势。从经济角度看，系统开发具有可行性。

**操作可行性**：系统采用B/S架构，用户通过浏览器即可访问，无需安装客户端软件。界面设计参考了主流管理后台的布局模式（左侧菜单 + 右侧内容区），采用 Element Plus 统一组件风格，操作逻辑符合用户使用习惯，学习成本低。同时，系统对必填字段和输入格式进行了校验提示，降低了用户操作错误率。从操作角度看，系统具有可行性。

### 3.2 功能需求分析

本系统围绕教学管理的核心业务流程，设计了八大功能模块：

**（1）登录模块**：用户通过用户名和密码登录系统。登录成功后生成 JWT Token，后续请求携带 Token 进行身份验证。未登录用户访问任何内部页面时自动跳转到登录页。支持登录失败次数限制，连续 5 次失败后账号锁定 15 分钟。密码采用 BCrypt 加密存储，不保存明文。

**（2）仪表盘模块**：登录后的首页，以统计卡片和图表形式展示平台核心数据概况。四个统计卡片分别展示学生总数、班级总数、今日出勤率和待批改作业数。两个图表分别为各班级学生人数分布柱状图和近 7 天出勤趋势折线图。数据实时从数据库查询，为管理员提供决策支持。

**（3）学生管理模块**：对学生信息进行增删改查管理。支持按姓名模糊搜索、按班级筛选、分页浏览。学生信息包括姓名、学号（唯一）、性别、所属班级、手机号、家庭住址。删除采用逻辑删除，删除前检查是否存在未批改作业并提示用户。学号在新增和编辑时校验唯一性。

**（4）班级管理模块**：对班级信息进行管理。每个班级需指定一名负责老师（从教师用户中选择），包含班级名称（唯一）、负责老师和描述信息。删除班级前校验是否还有学生和未完成的排课数据，存在关联数据时阻止删除并给出明确提示。

**（5）课程管理模块**：管理课程基础数据。课程信息包括课程名称、描述、默认授课老师和满分值（用于成绩范围校验）。为排课和成绩管理提供课程选项。

**（6）排课管理模块**：以周课表形式管理班级课程安排。课表为 5×8 表格（周一至周五 × 第1-8节课），每个格子显示课程名称和授课老师。排课时校验同一班级同一时段不能有两门课、同一老师同一时段不能给两个班上课。支持将课表复制到其他班级。

**（7）考勤打卡模块**：按班级和日期管理学生出勤情况。出勤状态分为出勤、迟到、请假、缺勤四种。支持一键将全班标为出勤后单独调整。同一学生同一天只能有一条考勤记录，重复打卡时覆盖旧记录。支持按日期范围查询历史考勤。

**（8）作业管理模块**：涵盖作业发布、提交、批改的完整生命周期。老师可发布作业（指定班级、课程、截止时间和满分值），查看提交情况（已提交/未提交/迟交），对已提交作业打分并写评语。超过截止时间提交的自动标记为迟交。打分不能超过作业设定的满分值。

**（9）成绩管理模块**：管理学生考试和作业成绩。支持按班级和课程批量录入成绩，也支持按学生查询其所有成绩记录。同一学生同一课程同一考试类型仅保留一条记录，重复录入时覆盖旧成绩。成绩范围根据课程满分值进行校验。

#### 4.1.2 系统架构设计

系统采用 B/S 三层架构：表现层（前端）、业务逻辑层（后端）、数据访问层（数据库）。

- **表现层**：Vue 3 + Element Plus + ECharts，运行在用户浏览器中，负责界面展示和用户交互，通过 HTTP 请求调用后端 API。
- **业务逻辑层**：Spring Boot 应用，接收前端请求，执行业务逻辑处理（参数校验、权限校验、冲突检测、数据转换等），通过 MyBatis 访问数据库。各功能模块对应独立的 Controller、Service、Mapper 三层。
- **数据访问层**：MySQL 数据库，存储用户、学生、班级、课程、排课、考勤、成绩、作业等业务数据。所有表采用逻辑删除和通用字段规范。

### 4.2 系统实现

#### 4.2.1 登录模块实现

登录页面采用居中卡片式布局，背景为蓝色渐变。用户输入用户名和密码后，前端进行非空校验，通过后发送 POST 请求至 `/api/login`。后端验证用户名密码（BCrypt 比对），检查账号是否锁定，验证通过后生成 JWT Token 返回。

核心代码（登录接口）：

```java
@PostMapping("/login")
public Result<Map<String, Object>> login(@RequestBody LoginRequest req) {
    // 参数校验
    if (req.getUsername() == null || req.getUsername().trim().isEmpty()) {
        throw new BusinessException(400, "用户名不能为空");
    }
    if (req.getPassword() == null || req.getPassword().trim().isEmpty()) {
        throw new BusinessException(400, "密码不能为空");
    }

    // 查询用户
    SysUser user = userService.findByUsername(req.getUsername());
    if (user == null) {
        throw new BusinessException(400, "用户名或密码错误");
    }

    // 检查账号锁定状态
    if (user.getStatus() == 0) {
        if (user.getLockedUntil() != null && user.getLockedUntil().after(new Date())) {
            throw new BusinessException(400, "账号已被锁定，请稍后再试");
        }
        // 锁定已过期，解锁
        userService.unlockUser(user.getId());
        user.setStatus(1);
        user.setLoginFail(0);
    }

    // 验证密码（BCrypt 比对）
    if (!passwordEncoder.matches(req.getPassword(), user.getPassword())) {
        int failCount = user.getLoginFail() + 1;
        userService.updateLoginFail(user.getId(), failCount);
        if (failCount >= 5) {
            // 锁定 15 分钟
            userService.lockUser(user.getId(), 15);
            throw new BusinessException(400, "连续 5 次登录失败，账号已被锁定 15 分钟");
        }
        throw new BusinessException(400, "用户名或密码错误");
    }

    // 登录成功，重置失败次数
    userService.updateLoginFail(user.getId(), 0);

    // 生成 JWT Token
    String token = jwtUtil.generateToken(user.getId(), user.getUsername());
    Map<String, Object> data = new HashMap<>();
    data.put("token", token);
    data.put("username", user.getUsername());
    data.put("realName", user.getRealName());
    data.put("role", user.getRole());

    return Result.ok(data);
}
```

```sql
SELECT c.class_name, COUNT(s.id) AS student_count
FROM class c
LEFT JOIN student s ON s.class_id = c.id AND s.is_deleted = 0
WHERE c.is_deleted = 0
GROUP BY c.id, c.class_name
ORDER BY student_count DESC

-- 近 7 天出勤趋势
SELECT a.attendance_date AS date,
       ROUND(SUM(CASE WHEN a.status = 1 THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 1) AS rate
FROM attendance a
WHERE a.is_deleted = 0 AND a.attendance_date >= DATE_SUB(CURDATE(), INTERVAL 7 DAY)
GROUP BY a.attendance_date
ORDER BY a.attendance_date
```

```java
public void addSchedule(Schedule schedule) {
    // 校验班级时间冲突（数据库唯一索引 uk_class_day_period 做最终保障）
    Schedule existing = scheduleMapper.findByClassDayPeriod(
        schedule.getClassId(), schedule.getDayOfWeek(), schedule.getPeriod());

        throw new BusinessException(400, "该时间段已有课程安排");
```

```java
public void batchSave(List<Attendance> list) {
    if (list == null || list.isEmpty()) {

}
```

#### 4.2.8 作业管理模块实现

作业模块覆盖发布→提交→批改的完整流程。提交时自动比较提交时间与截止时间，判定是否迟交。批改时校验得分不超过满分。

核心代码（提交作业-自动迟交判定）：

```java
public void submitHomework(HomeworkSubmission submission) {
    Homework homework = homeworkMapper.findById(submission.getHomeworkId());
    if (homework == null) {
        throw new BusinessException(400, "作业不存在");
    }
    submission.setSubmitTime(new Date());
    // 迟交判定：提交时间晚于截止时间
    if (submission.getSubmitTime().after(homework.getDeadline())) {
        submission.setSubmitStatus(2); // 迟交
    } else {
        submission.setSubmitStatus(1); // 已提交
    }
    homeworkMapper.insertOrUpdateSubmission(submission);
}
```

```java
public void gradeSubmission(Long id, BigDecimal score, String comment) {
    HomeworkSubmission submission = homeworkMapper.findSubmissionById(id);
    if (submission == null) {
        throw new BusinessException(400, "提交记录不存在");
    }
    Homework homework = homeworkMapper.findById(submission.getHomeworkId());
    if (score.compareTo(BigDecimal.ZERO) < 0) {

    if (homework != null && score.compareTo(new BigDecimal(homework.getMaxScore())) > 0) {
        throw new BusinessException(400,

    }

}
```

### 五、总结

本系统围绕教学数字平台的核心业务需求，完成了从需求分析、系统设计到编码实现的完整开发过程。系统实现了学生管理、班级管理、课程管理、排课管理、考勤打卡、成绩管理和作业管理共八大功能模块，覆盖了教学管理的日常核心业务场景。

系统在技术和工程方面具有以下特点：

**（1）安全性**：所有 SQL 使用 MyBatis `#{}` 参数化查询，杜绝 SQL 注入风险；密码使用 BCrypt 加密存储；接口通过 JWT Token 进行身份认证；所有接口均对输入参数进行校验。

**（2）数据一致性**：使用数据库唯一索引约束关键业务规则（如同一班级同时段不冲突、同一学生同一天唯一考勤记录），应用层和数据库层双重保障。

**（3）可维护性**：统一的项目结构和命名规范，Controller-Service-Mapper 三层分离，SQL 集中在 XML 映射文件中管理。所有表采用通用字段和逻辑删除策略。

**（4）用户体验**：前端使用 Element Plus 统一组件风格，表单均有输入校验，操作有成功/失败提示，删除敏感操作有确认弹窗。

**系统不足与改进方向**：

1. 当前未实现用户管理模块（新增/编辑/删除用户），管理员账号需要直接在数据库中插入；
2. 缺少操作日志记录功能，无法追溯用户的具体操作历史；
3. 暂未实现数据导出功能（如考勤报表导出 Excel），后续可在考勤和成绩模块中补充；
4. 仪表盘统计数据的时效性可进一步优化，引入缓存机制减少数据库查询压力；
5. 可引入前端单元测试和后端接口测试，提升代码质量和发布信心。
